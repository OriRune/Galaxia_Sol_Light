# Task 4.4 — Trails

Implemented two screen-resolution RGBA8 feedback textures with framebuffer ownership, resize replacement, previous/current camera reprojection, frame-rate-independent 1.2-second half-life, 35% current-star accumulation, below-star compositing, and target swapping. Trail state is renderer-only and never enters Worker state or digest calculation.

The exact clear reasons are scene replacement, zero-star topology, WebGL context restoration, and non-invertible camera. Automatic framing movement does not clear feedback. Teardown deletes both targets/framebuffers and the feedback program.

Focused verification:

- Three unit tests pass for the exact clear list, half-life independence, fixed-camera alignment, and scripted pan/zoom reprojection within two CSS pixels.
- Production viewport trail allocation passes in Chromium and Firefox and reports exactly two render textures/three total textures; teardown returns all counters to zero (10 browser tests total).
- TypeScript and ESLint pass.
- The locked exact-High 60-second smear gates are already passed by the accepted renderer design in ADR 0001 raw evidence; production normative rerun is grouped with Task 4.6 qualification.

Product integration audit: the top-bar Trails control now calls `PixiViewport.setTrails` and is coordinated as a UI-only undoable transaction. Scene load/import and undo restore the closed trails value; artwork capture continues to exclude editing overlays.
