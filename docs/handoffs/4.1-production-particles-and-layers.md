# Task 4.1 — Production particles and layers

Implemented the accepted WebGL2 instanced-quad renderer as the sole production star path. It owns one procedural same-origin 16×16 radial-alpha texture, one dynamic interleaved position buffer, one static byte style buffer, and the shared indexed quad. Static data uploads only on topology replacement; frames upload positions only. Rendering clears to opaque sRGB `(5, 8, 20)` and uses normal premultiplied-alpha source-over blending.

`PixiViewport` explicitly requires WebGL2, stops the Pixi ticker, delegates topology and frame application to the retained renderer, and destroys all owned GL resources before destroying Pixi. Test-build counters cover particles, textures, render textures, listeners, leases, and upload classes.

Focused verification:

- TypeScript app, Worker, and Node projects pass.
- ESLint passes with zero warnings.
- Procedural texture unit test passes.
- Pixi viewport browser suite passes in Chromium and Firefox (8 tests total).
- The browser suite verifies particle count, topology-only static updates, position-only frame updates, origin-clean canvas capture, and 500 scene replacements without resource-counter growth.

Core artwork, encounter rings, trails, and editing overlays occupy their specified ordered stages but are implemented in their dedicated later Task 4 packets.
