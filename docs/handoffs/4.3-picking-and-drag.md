# Task 4.3 — Picking and drag

Implemented the frame-synchronous 32-CSS-pixel hit grid with one-cell viewport border, copied projected star coordinates, static rendered radii/owner slots, linked cell indices, projected core discs, and retained frame identity. Picking tests the exact rendered star/core union, chooses the nearest projected core, and resolves exact ties to the larger scene index.

Implemented isolated center and velocity drag sessions. Center previews preserve the pointer offset, reject rather than clamp out-of-range positions, and track with the camera's exact screen/world mapping. Velocity previews use the 2 DU/VU handle scale, display the 20-VU boundary when invalid, and reject an invalid completion. Topology changes or disappearing IDs cancel; a valid session returns at most one mutation payload.

Focused verification:

- Five interaction unit tests cover star-only, core-only, empty, overlap distance, exact newest tie, returned-buffer independence, stale topology cancellation, one-pixel tracking, invalid rejection, and one-commit behavior.
- Full TypeScript and ESLint gates pass.
- Pixi viewport regression passes in Chromium and Firefox (8 tests total).

Product integration audit: `App` now wires viewport picking, deselection, panning, center dragging, and non-zero velocity-handle dragging. Escape/pointer cancellation is non-mutating, topology invalidation cancels the gesture, and pointer-up dispatches at most one Worker mutation. Acceptance `16-camera.spec.ts` exercises both a real center drag and a real velocity drag through the production viewport.
